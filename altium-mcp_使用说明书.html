Altium MCP 使用说明书

通过 Model Context Protocol (MCP) 让 AI 助手连接 Altium Designer，实现原理图/PCB 数据查询、设计审查、自动化操作

适用版本：Altium Designer 22+  |  运行环境：Windows 10/11  |  Node.js 20+  |  协议：MCP stdio

一、项目概述

altium-mcp 是一个 MCP 服务器，将 Altium Designer 暴露给 AI 助手（如 Claude、OpenCode 等）。AI 助手可以通过 MCP 协议调用工具，查询 PCB/原理图数据、驱动 DelphiScript 自动化、执行设计审查。

核心能力

能力域说明工具数
环境配置检测 Altium 安装、配置路径、健康检查3
工作区查询列出打开的项目和文档1
原理图读取导出元件、连线、网络、电源端口等1
原理图编辑放置元件、连线、网络标签、电源端口（11 个动作）1
PCB 读取层信息、设计规则、网络、元件、引脚7
PCB 写入移动元件、创建网络类、控制层可见性4
布局复制识别同封装元件组并复制布局2
库操作搜索元件、导入库目录3
输出作业运行 OutputJob 生成制造文件2
截图截取 PCB/原理图编辑器视图1
AI Skill9 个专业设计审查与建议技能9
设计原则：默认采用"建议模式"——AI 可以读取设计数据并给出建议，但写操作（修改原理图/PCB）被特性标志门控，默认禁用，需要手动开启。

二、快速开始

2.1 环境要求

项目要求
操作系统Windows 10/11
Altium Designer22+ 推荐（X2.EXE）
Node.js20+
MCP 客户端任何 MCP 兼容客户端（OpenCode、Claude Desktop 等）

2.2 安装步骤

# 安装依赖
npm install

# 编译 TypeScript
npm run build

# 启动 MCP 服务器
npm start

2.3 首次使用流程

1. get_server_status → 2. configure_altium_exe → 3. altium_ping → 4. get_workspace_projects → 5. 业务工具
  1. get_server_status：确认工作区路径和 X2.EXE 是否被发现（同时自动同步脚本到工作区）
  2. configure_altium_exe：如果 X2.EXE 未找到，用此工具配置路径
  3. altium_ping：验证 DelphiScript 桥接在 Altium 内响应
  4. get_workspace_projects：发现打开的项目和文档路径
  5. 业务工具：开始使用 PCB/原理图/库等工具
PCB 工具前置条件：使用 PCB 读取工具前，必须在 Altium 中聚焦目标 .PcbDoc 文档（点击使其成为活动文档）。

三、架构原理

3.1 工作流程

Node 写 request.json → 启动 X2.EXE -RScriptingSystem → DelphiScript 执行 Run → 写 response.json → Node 读取结果

3.2 关键机制

机制说明
请求文件Node 写 request.json 到工作区（默认 %USERPROFILE%\.altium-mcp\workspace）
脚本启动通过 -RScriptingSystem:RunScript 启动 Altium 并运行 Altium_API.PrjScr
响应文件DelphiScript 执行后写 response.json
文件锁.bridge.lock 序列化并发工具调用（等待 60s，超时 120s）
错误日志失败时写 bridge_last_error.txt

3.3 坐标单位

场景单位说明
原理图坐标milsx_mils, y_mils
PCB 读取milsget_component_pins, get_selected_components
PCB 写入mils × 10000PCB 内部单位，set_component_position 用

四、MCP 工具详解

共 25 个工具，按功能域分组。标注 只读 写入 默认禁用 表示工具性质。

4.1 环境配置

get_server_status 只读

用途：检查 MCP + Altium 桥接配置

参数：无

返回：JSON { platform, workspaceRoot, altiumExeFound, scriptProjectFound, bundledScriptsDir, bridgeLastError, diagnosticsHint, env }

首次调用会自动同步脚本包到工作区 AltiumScript/ 目录。
configure_altium_exe 配置写入

用途：保存 Altium X2.EXE 路径到配置文件

参数：

  • path (string, 必需)：X2.EXE 的绝对路径

返回：{ ok, altiumExePath }

altium_ping 只读

用途：验证 DelphiScript 桥接在 Altium 内响应

参数：无

返回：{ success, result: { protocolVersion, pong } }

4.2 工作区查询

get_workspace_projects 只读

用途：列出打开的工作区条目（项目 + 文档）

参数：无

返回：JSON { projectCount, focusedProjectFullPath, projects[].{ index, projectFullPath, projectFileName, documents[].{ kind, fullPath, fileName } } }

包含非设计条目（Free Documents, AltiumScript）。

4.3 原理图读取

get_schematic_data 只读

用途：导出原理图纸数据，支持按 bucket 过滤

参数（全部可选）：

  • schematic_full_path：.SchDoc 绝对路径（优先）
  • project_full_path：.PrjPcb/.PrjScr 绝对路径
  • schematic_sheet_file_name：文件名（如 Sheet1.SchDoc）
  • include_queries：string[] 过滤器，支持：sheet | components | wires | buses | net_labels | power_ports | text_labels | junctions | ports | off_sheet_connectors | sheet_symbols | directives | figures | harness | drawing_objects | all。省略 = 默认 { components, drawing_objects }

返回：按请求 bucket 分组的 JSON 数组，坐标单位 mils

定位优先级：schematic_full_path > project_full_path + sheet > 聚焦项目

4.4 原理图编辑

edit_schematic 写入 默认禁用

用途：基于 action 的单工具原理图编辑

启用：需设置 ENABLE_SCHEMATIC_WRITES = true

参数：

  • action (必需)：动作类型
  • schematic_full_path 或 project_full_path + schematic_sheet_file_name

支持的 11 个动作：

Action说明关键参数
set_component_transform移动/旋转元件designator, x_mils?, y_mils?, rotation_deg? (0/90/180/270)
set_component_parameters设置元件参数designator, parameter_names[], parameter_values[]
place_component放置元件lib_reference, designator, x_mils, y_mils, rotation_deg?, sch_library_path
add_text添加文本text, x_mils, y_mils
add_net_label添加网络标签net_name, x_mils, y_mils, rotation_deg?
add_wire添加导线wire_points_csv (如 "0,0,1000,0,1000,500")
add_bus添加总线同 add_wire
add_bus_entry添加总线入口wire_points_csv (4 个数)
place_power_port放置电源端口power_port_style, x_mils, y_mils, net_name?, rotation_deg?
place_gnd放置 GNDx_mils, y_mils (默认 style=gnd_power, net=GND)
place_vcc放置 VCCx_mils, y_mils (默认 style=arrow, net=VCC)
不自动保存。操作后需用户手动在 Altium 保存。建议操作后用 get_schematic_data 验证。

4.5 PCB 读取

所有 PCB 读取工具要求用户先在 Altium 中聚焦 .PcbDoc 文档。
get_pcb_layers 只读

用途：列出电气/机械层元数据

返回：层列表，含名称、类型、可见性

get_pcb_rules 只读

用途：列出 PCB 设计规则

返回：规则描述（名称、类型、作用域）

get_all_nets 只读

用途：列出 PCB 上所有网络名

返回：String[] 网络名

get_pcb_layer_stackup 只读

用途：物理层叠结构（介电层、厚度）

返回：层叠结构 JSON

get_all_designators 只读

用途：PCB 上所有元件参考位号

返回：String[] designators

get_component_pins 只读

用途：指定元件的引脚级数据

参数：designators (string[], 必需, 至少 1 个)

返回：每个 designator 的引脚信息（pinNumber, netName, padX, padY, layer）

get_selected_components 只读

用途：获取当前选中 PCB 元件的坐标

返回：JSON[] { designator, x, y, rotation }，无选择则空

用户需先在 Altium PCB 编辑器中选择元件。

4.6 PCB 写入

所有 PCB 写入工具默认禁用，需设置 ENABLE_PCB_WRITES = true 并重新编译。
set_component_position 写入

用途：移动单个 PCB 元件到绝对位置

参数：designator, x (mils×10000), y (mils×10000), rotation? (度)

move_components 写入

用途：批量相对移动 PCB 元件

参数：designators[], x_offset (mils), y_offset (mils), rotation? (度, 默认 0)

create_net_class 写入

用途：创建网络类并添加网络（已存在则只加新成员）

参数：class_name, net_names[]

不存在的网络名会被静默跳过。
set_pcb_layer_visibility 写入

用途：切换 PCB 层可见性

参数：layer_names[] (显示名), visible (bool)

4.7 布局复制

layout_duplicator 只读

用途：查找相同封装的元件组，用于布局复制

返回：元件组列表，含源/目标候选

layout_duplicator_apply 写入 默认禁用

用途：从源元件复制布局几何（走线/圆弧/填充/过孔）到目标元件

参数：source_designators[], destination_designators[]

要求源/目标封装匹配。

4.8 库操作

get_library_symbol_reference 只读

用途：获取项目元件的库符号引用

返回：JSON[] { lib_reference, footprint, description, library_path }

search_library_symbol 只读

用途：按名称搜索原理图符号

参数：

  • symbol_name (必需)：符号名
  • library_path (可选)：指定 .SchLib 路径，省略则搜全部已安装库
空 symbol_name + 指定 library_path 可枚举 IntLib 中所有元件。
import_library_components 推荐

用途：枚举项目目录 .SchLib 中所有元件并缓存目录到记忆

参数：library_path (string, 必需)：.SchLib 绝对路径（仅项目目录）

返回：{ success, library_name, component_count, project_name, memory_files, sample_components[] }

关键：导入后优先读 memory/short-term/{project}/library-catalog.md 来解析 lib_reference + sch_library_path，避免重复查 Altium。
仅支持项目目录下的 .SchLib，不要指向 AD 默认库目录。

4.9 输出作业

get_output_job_containers 只读

用途：列出 .OutJob 文件中的输出容器

返回：JSON[] { name, outputType, enabled }

run_output_jobs 生成文件

用途：执行输出作业容器，生成制造文件

参数：container_names (string[], 必需)

返回：{ success, output_file_paths }

4.10 截图工具

take_view_screenshot 只读

用途：截取 PCB 或原理图编辑器视图为图片

参数：view_type ("pcb" | "sch", 可选, 默认 "pcb")

返回：{ screenshot_file_path }

file_mode_capabilities 只读

用途：报告离线文件模式能力（仅 Node，无 Altium 进程）

返回：能力标志 JSON

create_schematic_symbol 写入 默认禁用

用途：在 SchLib 中创建新原理图符号

启用：需设置 ENABLE_SYMBOL_CREATION = true

参数：symbol_name, pins[] ("number,name,type"), part_count?, description?

五、AI Skill 技能

项目内置 9 个专业设计 Skill，是面向 AI 助手的提示词模板，覆盖从电路设计到文档生成的完整流程。Skill 标记。

5.1 电路拓扑建议 Skill

核心功能：根据用户描述的电路意图，推荐电路拓扑结构、计算元件值、解释设计权衡

输入：电路功能需求、性能指标（如输入/输出电压、电流、效率要求）

输出：结构化的拓扑方案，含推荐电路图、元件参数、设计要点

使用场景：

  • 设计新电路功能时，需要选择合适的拓扑结构
  • 要求计算元件参数（电阻、电容、电感值）
  • 对比不同拓扑的优劣

典型对话："我需要一个 5V 转 3.3V 的电源，最大电流 2A，效率不低于 90%"

5.2 元件选型与连接方案 Skill

核心功能：根据电路需求匹配推荐元件并生成选型报告与连接方案

输入：用户需求描述 + 记忆中的库元件信息（来自 import_library_components）

输出：元件选型报告 + 连接方案

使用场景：

  • 描述电路功能需求，要求元件选型
  • 生成元件连接方案
  • 结合库目录记忆推荐合适的元件

典型对话："帮我选一个低功耗运放，用于电池供电的传感器信号放大"

5.3 原理图审查审计 Skill

核心功能：读取 Altium 原理图数据，分析元件连接关系，生成审查审计报告

输入：原理图数据（get_schematic_data 结果）+ 长期记忆

输出：结构化审计报告，含问题清单、风险点、改进建议

使用场景：

  • 审查原理图连接关系正确性
  • 检查设计规范遵守情况
  • 审计设计完整性和潜在风险

5.4 设计规则推导 Skill

核心功能：根据电路意图生成 DRC 设计规则配置建议

输入：电路类型、性能指标、工艺要求

输出：设计规则建议报告（线宽、线距、过孔、阻焊、铺铜规则）

使用场景：

  • 设置/检查 DRC 规则
  • 确定线宽线距要求
  • 定义过孔/阻焊/铺铜规则

典型对话："这个板子有 USB 3.0 差分对，帮我推导需要的 DRC 规则"

5.5 布局策略建议 Skill

核心功能：根据电路拓扑建议 PCB 布局策略

输入：PCB 元件数据 + 原理图数据

输出：布局策略报告（功能分区、元件摆放建议、关键路径）

使用场景：

  • PCB 布局规划
  • 元件摆放建议
  • 功能分区规划

5.6 信号完整性建议 Skill

核心功能：根据 PCB 层叠结构和信号类型推导线宽、线距、阻抗控制规则

输入：PCB 层叠结构、设计规则、信号类型

输出：信号完整性设计指导报告

使用场景：

  • 阻抗匹配分析
  • 差分对走线规则
  • 高速信号完整性评估

典型对话："4层板，TOP-GND-PWR-BOTTOM，50Ω 单端阻抗怎么走？"

5.7 PCB 设计审查顾问 Skill

核心功能：读取 PCB 设计数据执行综合审查，含原理图-PCB 一致性检查

输入：PCB 数据 + 原理图数据

输出：结构化综合审查报告

使用场景：

  • 设计审查（DRC 之外的设计合理性）
  • 原理图-PCB 一致性检查
  • 网络命名规范检查

5.8 BOM 分析与优化 Skill

核心功能：审查 BOM 物料清单，分析单一来源、生命周期、替代料

输入：原理图中的元件数据

输出：BOM 分析报告（风险元件、替代料建议、采购优化）

使用场景：

  • 分析 BOM 物料风险
  • 检查单一来源零件
  • 元件生命周期状态评估
  • 优化采购成本

5.9 设计文档生成器 Skill

核心功能：分析设计数据，自动生成电路功能说明、设计决策记录、评审文档

输入：设计数据 + 长期记忆

输出：结构化文档（设计说明书、决策记录、评审材料）

使用场景：

  • 生成设计说明书
  • 记录设计决策
  • 准备评审材料
  • 输出技术文档

六、典型使用场景

场景 1：新项目启动检查

1. get_server_status     // 检查环境
2. altium_ping           // 验证桥接
3. get_workspace_projects // 列出项目
4. get_schematic_data     // 读取原理图
   include_queries: ["components", "net_labels", "power_ports"]
5. get_pcb_layers        // 读取 PCB 层（需先聚焦 PcbDoc）
6. get_all_designators   // 列出元件

场景 2：原理图审查

1. get_schematic_data
   schematic_full_path: "C:\\项目\\Sheet1.SchDoc"
   include_queries: ["all"]
2. 调用 skill-schematic-audit 进行审查
3. 调用 skill-bom-analyzer 分析物料
4. 生成审查报告

场景 3：PCB 设计审查

1. 聚焦目标 .PcbDoc
2. get_pcb_layer_stackup  // 层叠结构
3. get_pcb_rules          // 设计规则
4. get_all_nets           // 网络列表
5. get_all_designators    // 元件列表
6. get_component_pins     // 关键元件引脚
   designators: ["U1", "U2", "J1"]
7. 调用 skill-design-review-advisor 综合审查
8. 调用 skill-signal-integrity-advisor 高速信号分析

场景 4：元件选型与放置

1. import_library_components  // 导入库目录
   library_path: "C:\\项目\\libs\\my.SchLib"
2. 读取 memory/short-term/{project}/library-catalog.md
3. 调用 skill-component-selection-prompt 选型
4. （启用写操作后）edit_schematic place_component 放置元件

场景 5：布局复制

1. 聚焦 .PcbDoc
2. layout_duplicator  // 查找同封装元件组
3. 确认源/目标映射
4. （启用写操作后）layout_duplicator_apply 复制布局

场景 6：生成制造文件

1. get_output_job_containers  // 列出 OutJob 容器
2. run_output_jobs             // 执行
   container_names: ["Gerber Files", "Drill Files", "BOM"]

七、错误处理

错误原因解决方法
AD_NOT_FOUNDX2.EXE 路径错误调用 configure_altium_exe 设置正确路径
SCRIPT_PROJECT_NOT_FOUND脚本包未同步调用 get_server_status（自动同步）
TIMEOUT脚本挂起或断点清除 Altium IDE 断点；删除 .bridge.lock
LockTimeout上次崩溃留下锁删除工作区目录下的 .bridge.lock
空数据PCB 未聚焦在 Altium 中聚焦 .PcbDoc
INVALID_BRIDGE_RESPONSEJSON 解析失败检查 bridge_last_error.txt
锁文件位置：默认在工作区目录 %USERPROFILE%\.altium-mcp\workspace\.bridge.lock。删除此文件可解除死锁。

八、记忆协议

为减少工具调用和上下文消耗，系统维护两级持久化记忆。

8.1 短期记忆（short-term）

项目说明
位置memory/short-term/{项目名}/{文件名}.md
保存时机首次查询后立即写入
加载时机会话开始时自动加载
生命周期当前项目/文件的整个会话期间

8.2 长期记忆（long-term）

项目说明
位置memory/long-term/{项目名}.md
保存时机用户主动要求保存设计知识时
加载时机进入项目时自动加载
生命周期跨会话持久保留

8.3 记忆格式

## MEM:PCB_COMP 2026-01-15T10:35
@U1 F:QFP-48 X:3500 Y:2100 R:0
@R1 F:0603 X:1500 Y:800 R:90

## MEM:SCH_COMP 2026-01-15T10:30

ENABLE_SYMBOL_CREATIONcreate_schematic_symbolfalse
安全提示：启用写操作后，AI 助手可以修改你的设计文件。建议在启用前：

  • 密切关注 AI 的每一步写操作
