# Altium Designer MCP 服务器开发日志

> 项目：altium-mcp
> 开发周期：2026-09-12 ~ 2026-09-14
> 主题：AI 绘图质量根因分析与三阶段流水线落地——连线阶段工具化（端点吸附 / wire_pins / optimize_layout / draw_plan）、选型阶段工具化（pin_table / validate_netlist）、库枚举重大修复、AD22 实机全链路验证

## 阶段背景

用户核心反馈：工具本身实现没问题，但 AI 绘制原理图时连接错误、位置放置不当——"画不出好看的原理图"。本周从根因分析出发，确立**三阶段流水线**架构（① 选型+网表 → ② 放置 → ③ 连线，黄金网表作为贯穿全链路的单一事实源），并把第 ①、③ 两个阶段从"提示词约束"升级为"工具承接"：

- 第 ③ 阶段（连线）：模型只给拓扑，工具读真实引脚热点、避障布线、自动结点、机器验证
- 第 ① 阶段（选型）：模型对着真实库引脚表设计网表，机器校验后才允许进入下游
- 第 ② 阶段（放置）：optimize_layout 事后寻优已就位，事前规划 plan_placement 待做

## 1. 根因分析：提示词问题 vs 工具架构问题

| 层面 | 结论 | 证据 |
|------|------|------|
| 工具架构（主因） | 精确几何计算交给了模型：add_wire 无吸附，1 mil 偏差即浮空；A* 路由器与爬山法优化器已写好但躺在 trash/test/ 未进工具面 | fixAndApply.mjs（689 行，已验证 73 线网表等价）与 optimizePlacement.mjs（613 行，评分 594→292）均在垃圾目录 |
| 提示词（次因） | 坐标系约定未声明（Y 轴向上/旋转逆时针）；"2 引脚符号默认水平"与实战教训 YAML 矛盾（真实情况按符号各异）；指令超长且 PCB/原理图混杂稀释注意力 | 项目自身 DEVLOG 就栽过 "Altium Y 轴向上导致导出高度为负" 的坑 |
| 模型特性 | 长上下文数字转录 + 心算几何是 LLM 最弱项，修复闭环依赖同一套易错算术 → "修不好、循环修" | led-indicator-circuit.yaml 修复版 v2 的人工迭代记录 |

**核心结论：模型负责拓扑与意图，工具负责几何与验证；"1 mil 浮空"这类硬约束应由工具吸收，不应出现在提示词里。**

## 2. P0-1：服务端端点吸附（schematic_edit.pas）

- `SchEditCollectSnapTargets`：收集全表可见引脚热点（Pin.Location + PinLength 沿朝向，与 get_component_info 同一数学）+ 电源端口位置（ISch_PowerObject 经 ISch_Label 读 Location，schematic_utils.pas 已验证模式）
- `add_wire`：折线**首末点**（电气端点）在容差内（默认 20 mil，`snap_tolerance_mils` 可调，0 关闭，上限 50）吸附最近热点；**中间拐点永不吸附**（拐点误触无关引脚 = 制造短路）；非吸附点对齐 10 mil 栅格；零长段跳过；响应回报 `points_csv`（实际绘制坐标）+ `snapped[]`（from/to/target 明细）
- `place_gnd / place_vcc / place_power_port`：默认 25 mil 吸附，回报最终坐标与 `snapped_to`

## 3. P0-2：A* 路由器与爬山法晋升为 MCP 工具

### 3.1 schematicRouter.ts（共享路由核心）

从 fixAndApply.mjs / optimizePlacement.mjs 提取：segRel 线段关系（none/cross/touch/overlap，X 交叉=安全）、网络感知 Dijkstra（转向惩罚 80、障碍余量 700 mil）、曼哈顿 MST、T 接 junction 检测、computeWireNets、partitionOf 电气等价签名。**新增 chooseGrid 自适应网格**（100/50/20/10 mil 取最大可整除者），解决原路由器"引脚不在 100 网格即抛 off-grid"死穴。

### 3.2 wire_pins 工具

`wire_pins(net_name, pins=["R1.2","D1.1",...])`：模型只给拓扑。流程：读真实引脚热点 → MST → A* 避障布线（异网导线/引脚为障碍，本网可搭接）→ 自动 junction → **单次 draw_plan 落地** → 复核"所有列出引脚落同一网络"。规划全程内存完成，失败零写入。布线前**跨网络引脚热点碰撞守卫**（见 B26）。

### 3.3 optimize_layout 工具

内存爬山（4 旋转 × ±100/200/300 mil 平移 × 元件重叠约束，复用 analyzeSchematicQuality 估算器）→ draw_plan 应用变换 → **重读真实引脚坐标** → 删全部导线按**基线网表**全图重布 → junction → 网表分区等价验证。重布规划失败**自动回滚**（恢复原变换+原导线+junction）。

### 3.4 draw_plan 批量动作（Pascal）

一次桥接调用依次执行 transforms_csv → delete_wires_all → wires_csv → junctions_csv。**数组元素内部分号分隔**——桥接行解析器（SchEditParseStringArray）会剥掉所有引号和逗号，逗号无法在数组元素内存活。导线坐标为路由器精确输出，刻意不吸附不取整。

## 4. 提示词重构（mcpInstructions.ts）

- 绘图工作流改为三阶段结构：STAGE 1（知识库检索 → pin_table → 写网表 → validate_netlist 冻结）→ STAGE 2（粗放元件）→ STAGE 3（wire_pins → 电源对象 → check_connectivity 分区比对 → optimize_layout → 重放标签）
- 删除"2 引脚符号默认水平"错误断言，改为指向 pin_table / get_component_info 的逐符号数据
- 显式声明坐标系：mils、Y 轴向上、原点左下、旋转逆时针
- "EXACTLY / 1 mil 浮空"类对抗性约束降级为背景说明（容错已由工具承接）

## 6. 第一阶段工具：pin_table + validate_netlist

### 6.1 pin_table

放置前的库引脚定义表：编号、名称、电气类型、朝向（0/90/180/270）、位置、长度、推导的 **hotspot_dx/dy**（热点偏移，与放置后 get_component_info 同一数学）。数据通路 = 修复后的 get_library_symbol_reference（见 §7）。重名符号上报 also_in_libraries；多部件符号引脚号去重。

### 6.2 validate_netlist

黄金网表机器门禁，双模式：

| 模式 | 检查项 |
|------|--------|
| pin-tables（默认，对照真实库引脚） | PIN_NOT_ON_COMPONENT（幻觉引脚，附可用引脚清单）/ PIN_IN_MULTIPLE_NETS（一脚两网=构造性短路）/ 逐元件未分配引脚清单（整件遗忘=零分配）/ POWER_PIN_OFF_POWER_NET / POWER_NET_NO_POWER_PIN |
| syntax-only（无库回退） | 引脚格式 / 未声明位号 / 重复位号·网络·引脚 / 空网·单脚网 / 命名规范 |

通过返回 `frozen_netlist` 作为下游 wire_pins / check_connectivity 的比对基准。

### 6.3 提示词

绘图工作流头部插入 STAGE 1（知识库 → pin_table → 写网表 → validate_netlist 冻结），Tool Quick Map 增加 Planning 行。

## 7. 重大既有修复：库枚举从未真正工作过

get_library_symbol_reference（及同源 search_library_symbol、list_library_components）一直返回 0 元件——index.ts 里的内存缓存兜底即为此而设的历史补丁。两个根因：

1. **B27**：库文档上用 `SchIterator_Create` 枚举元件——它枚举的是"当前编辑中的元件"，恒为空。正确方法 `SchLibIterator_Create`（对照 OpenLib/libUtils.pas L166），共 6 处全部修复
2. **B28**：Phase 1（聚焦库）抢跑——只要 AD 恰好聚焦一个 SchLib 就只枚举它、跳过全部工程库。改为工程库优先全量枚举，聚焦库仅作无工程库回退

附带：库文档解析改 GetSchDocumentByPath（焦点无关，SchEditResolveSheet 已验证模式）、OpenDocument kind 字符串三连尝试、pin_length_mils 导出、library_debug 调试字段。**修复后实机：611 元件 / 3 库（此前 0）。**

## 本周经验沉淀

1. **工具要求模型零失误 vs 工具吸收小失误**：LLM 无法保证几十次调用中每个坐标数字一字不差，"EXACTLY 匹配"类硬约束必须由工具端承接（吸附/回读），提示词只描述意图
2. **确定性算法能做好的事（布线、布局寻优）绝不让模型在上下文里手工模拟**——画不好看的根源就是把组合优化问题交给了逐 token 推理
3. **实测是唯一可信度**：本周三个"从未工作过/已失效"的既有功能（open_document PRJPCB、库枚举、截图）全部是实机测试挖出来的，代码审查和单测都放过了它们
4. **排障先验证工具链，再怀疑代码**：node -e 内联脚本的 4 连反斜杠转义制造了"路径解析失灵"假象，浪费了一轮排障——手写测试脚本的转义层数要先排除
5. **几何上无解的要在入口拦截**：异网引脚热点物理重合，任何布线都必然短路——工具前置检测 + 明确报错（挪哪个元件、挪多远），好过画完再让验证层抓

### B30：元件 BoundingRectangle 对旋转符号不可信

R1(rot270) 导出包围盒 [7900,7960]×[1060,1500] **甚至不含自己的引脚热点** (7800,1600)；J1(rot180) 同样矛盾（Pascal 用的已是官方 `Component.BoundingRectangle`）。**修复：放弃导出包围盒，改用实测数据构造禁入区**——`componentKeepOutRects()`：每元件"引脚热点 ∪ 原点"凸包（对向引脚=本体跨度；同向引脚=原点在体内补全），天然抗旋转。教训：**凡是能实测的几何就不要信导出值**。

### router / 标签放置两项通用能力

1. **本体禁入区**（wirePins→routePair `bodyRects`）：凸包内部节点封锁 + **边穿越检查**（100mil 网格一步可跨过 80mil 薄阻挡带而无内部节点——开区间盒重叠判定堵住）。实测效果：GND 绕行从穿 J1 本体改为沿本体左缘干净下行。
2. **标签碰撞回避**（instantiateModule `pickLabelAnchor`）：候选点沿本网导线每 50mil 采样，文本框（60mil/字符×110 高）对凸包和已放标签做碰撞检验，优选水平段→靠下→靠左；全碰撞则回退旧锚点。实测：VIN_RAW/VIN/EN 三标签全部落在净空区。

## 补记 2026-09-15（傍晚）：锚点引脚放置（anchor_pin）——旋转甩位问题的结构性消除

用户点破机制：**AD 旋转元件绕 Location 原点（通常偏心）转动，转 90° 整个符号甩位**——这就是引脚朝向错乱与 B30 包围盒失真的根源。结构性解法落地：放置语义从"放原点"升级为"放接口点"。

### 实现

| 层 | 内容 |
|----|------|
| `pinTable.ts` | `rotateOffsetCCW`（CCW 旋转矩阵，**实机标定**：Res1 rot90/270、Header2 rot0/180、Cap rot270、Diode rot0 全部复现实测偏移）+ `pinHotspotOffsetAtRot0`（库引脚数据 → rot0 热点偏移） |
| `moduleTemplates.ts` | 模板元件可选 `anchor_pin`（布局偏移=该引脚热点目标）；`anchoredOrigin`（origin = target − rotate(rot0偏移, θ)）；`findTemplatePin` 大小写无关查找 |
| `instantiateModule.ts` | 放置环节：锚点槽位矩阵反解原点 → 放置 → **回读锚点引脚实测位置 → 偏差>5mil 自动 set_component_transform 纠偏**（自愈，矩阵万一失准也不出错） |
| `edit_schematic`（index.ts 拦截） | `place_component` 直接暴露 `anchor_pin` 参数：拦截 → 查库引脚表 → 重写 x/y → 转发（MCP 工具面同享） |
| 模板 v4 | buck-input-stage 全槽位锚点化：模块原点=VIN_RAW 轨入口，layout 即轨道坐标（D_REV.3@600、C_BULK.1@1500、R_UV1.1@2600 同轨 y=0） |

### 实机验收（Sheet2 v4，124s）

- 六个元件矩阵反解原点与实测**逐 mil 一致，零纠偏触发**（J1@(5300,1400) 等全部命中预测）
- **VIN 轨 y=1500 一条直线穿 D1.1/C1.1/C2.1/R1.1 四热点——v3 的 100mil 台阶消失**（锚点语义的天然收益：轨道对齐由构造保证，不再依赖手工反解）
- 三标签净空（VIN_RAW@5550 在 600mil 槽、VIN@6650 在 D1/C1 间、EN@850 在 300mil 中缝）；GND 端口挂 C1.2
- 电气：4 网编译全过 all_module_nets_compiled=true
- 测试 **101/101**（新增锚点 4 例：矩阵复现实测值、rot0 偏移推导、anchoredOrigin 反解、findTemplatePin）

### 模板 authoring 语义升级

v3 及以前：layout = 原点偏移（需手工校准每符号每旋转的引脚甩位）。
v4 起：layout = **接口点坐标**（"VIN 轨在 y=0，C_BULK.1 落 x=1500"）——新模板不再需要测量-反解循环，旋转甩位被工具完全吸收。
