# 知识库扩展指南 — 如何为 altium-mcp 添加知识库内容

> 适用版本：2026-09（week8）
> 读者：后续为本项目添加知识库内容的开发者
> 原则：**添加知识 = 写对格式的 .md 文件 + 重建索引 + 重启服务 + 验证检索**，四步缺一不可

***

## 1. 知识库工作原理（先懂机制，再写内容）

### 1.1 数据流

```
knowledge-base/**/*.md  --(npm run build-kb)-->  knowledge-base/kb-index.json
        (人工编写)              scripts/build-kb-index.mjs         (TF-IDF 索引)
                                                                   |
MCP 客户端 --search_knowledge_base(query)--> kbSearch.ts 懒加载索引（内存缓存）
                                              TF-IDF + 关键词 + 实体标签 + 分类加权打分
                                              --> 返回 ranked chunks
```

### 1.2 核心机制：按 H2 标题分块

索引器（[kbIndexer.ts](../src/knowledge-base/kbIndexer.ts#L264-L342)）把每个 .md 文件按 `##` 二级标题切成 chunk：

- **第一个** **`##`** **之前的内容**（H1 标题 + 元信息）成为一个 preamble chunk

- **每个** **`##`** **章节成为一个独立 chunk**，检索返回的是章节级内容，不是整篇文件

- `###` 及以下标题**不会**产生新块，归属所在 `##` 章节

- 代码块（\`\`\` 围栏）内的 `##` 不会被误认为标题

**这意味着：`##`** **的写法直接决定检索质量。** 一个 `##` 章节应当主题自包含（用户搜这个主题时，返回这一块就够用），且标题要包含可被检索的实义词（如 `## 电容选型与计算` 优于 `## 选型`）。

### 1.3 检索打分

[kbSearch.ts](../src/knowledge-base/kbSearch.ts#L325-L425) 对 query 与每个 chunk 做：

| 信号           | 说明                                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| TF-IDF 向量相似度 | 主信号；词汇表来自全库分词                                                                                           |
| 关键词命中        | query 词项在 chunk 中的命中                                                                                    |
| 实体标签         | 器件名/型号等实体加权                                                                                             |
| 分类加权         | 可选 `category` 参数过滤：classic-circuits / design-rules / component-selection / drc-templates / power-supply |

**写作启示：正文要自然出现用户会搜的词**（中英文器件名、拓扑名、参数名，如 "LDO"、"TVS"、"退耦电容"、"decoupling"），不要只用行话简称。

### 1.4 索引是静态文件，且运行时有内存缓存

- `kb-index.json` 只在执行 `npm run build-kb` 时重新生成——**新增/修改 .md 后不重建索引，检索完全无感知**

- 服务进程首次搜索时把索引加载进内存并缓存（[kbSearch.ts](../src/knowledge-base/kbSearch.ts#L115-L167)）——**重建索引后不重启 MCP 服务，旧索引仍在内存中生效**

## 2. 目录结构与分类

### 2.1 现有结构

```
knowledge-base/
├── kb-index.json              # 索引（构建产物，勿手编）
├── classic-circuits/          # 经典电路模块
│   ├── README.md              # 本分类的总索引（人工维护）
│   ├── modules/               # 设计模块 .md（编号命名：01-xxx.md）
│   ├── review/                # 审查指南
│   └── agents/                # 预留
├── component-selection/       # 元件选型
├── design-rules/              # 设计规则
├── drc-templates/             # DRC 模板
├── gjb5000b/                  # GJB5000B 标准（注：见 2.3 同步事项）
└── power-supply/              # 电源设计
│   ├── modules/  review/  standards/  agents/
```

### 2.2 分类 = 一级目录名

索引器递归发现所有 .md，**category 取自一级目录名**。往现有分类添加内容只需放入对应目录的 `modules/`（设计知识）或 `review/`（审查知识）子目录。

### 2.3 新建分类的同步事项（易遗漏）

新建一级目录会自动被索引，但以下三处需要**手工同步**，否则新分类"存在但不可见"：

| 位置                                                               | 需要改什么                             |
| ---------------------------------------------------------------- | --------------------------------- |
| [src/index.ts](../src/index.ts) search\_knowledge\_base 注册处      | description 中的 category 枚举列表与分类简介 |
| [src/index.ts](../src/index.ts) 中 category 参数的 Zod enum/describe | 补充新分类名                            |
| 新分类目录下                                                           | 创建 README.md 总索引（沿用其他分类的格式）       |

> 实例：磁盘上已有 `gjb5000b/` 目录，但工具描述的枚举仍是 5 个分类——新分类不同步枚举就会出现这种"半接入"状态。修改后需 `npm run build` 重新编译。

## 3. 文件编写规范

### 3.1 命名

- 放入 `modules/` 时使用**两位编号前缀 + 主题**：`NN-topic-name.md`（如 `13-transistor-oscillator-led.md`），编号决定目录内排序

- 编号只在同目录内保证唯一，新文件接续当前最大号

### 3.2 文件模板

```markdown
# <主题名>（H1，唯一，索引会把它作为 preamble chunk 的标题）

> 适用范围：<什么场景用这份知识>
> 目标受众：<AI 设计流程 / 审查流程 / 人工>
> 版本：v1.0 | 更新日期：2026-09-01

## <实义章节标题>（每个 ## 是一个检索单元，务必自包含+含关键词）
背景/原理说明……

## 典型参数表（表格是 AI 引用的主要形态）
| 参数 | 典型值 | 说明 |
|------|--------|------|
| R1/R4 基极电阻 | 47kΩ | 与 C1/C2 共同决定频率 |

## 器件选型
……

## 常见错误与审查要点
……
```

### 3.3 写作要点（直接影响检索命中）

1. **`##`** **章节自包含**：返回该章节即可回答问题，不依赖其他章节的上下文
2. **`##`** **标题用实义词**：`## 电解电容选型与耐压计算` > `## 选型`
3. **正文覆盖中英文检索词**：`LDO（低压差线性稳压器）`、`TVS（瞬态电压抑制二极管）`
4. **参数用表格**，不用散文罗列——AI 引用和复核都方便
5. **数值带单位与条件**：`47kΩ @ 5V`，不要裸写 `47k`
6. **控制章节长度**：单章节建议不超过 \~80 行；过长主题拆成多个 `##`

### 3.4 内容来源纪律（项目核心规矩）

**新代码不凭空捏造参数，新知识同理**：参数表中的典型值必须有出处（器件 datasheet、权威教材、实测），来源写在章节内或文件头部。参考代码时以 `scripting-reference-master` 等标准库为准。

## 4. 添加流程（完整闭环）

```powershell
# 1. 写文件（按第 3 节规范）
#    knowledge-base/<分类>/modules/NN-topic.md

# 2. 重建索引
npm run build-kb

# 3. 重启 MCP 服务（清掉内存中的旧索引缓存）

# 4. 验证统计（确认文件数/chunk 数增长）
#    调用 get_knowledge_base_stats
#    预期：totalFiles / totalChunks 增加，categories 包含目标分类

# 5. 验证检索（用用户视角的真实 query 实测）
#    调用 search_knowledge_base { query: "<主题的自然语言查询>" }
#    预期：新文件的目标章节出现在 top 结果，score 合理
```

**验证不通过时的排查顺序**：

| 症状             | 原因                    | 处理                         |
| -------------- | --------------------- | -------------------------- |
| stats 中文件数没变   | 忘了 `npm run build-kb` | 执行后重启服务再查                  |
| stats 变了但搜不到   | 服务没重启，内存缓存旧索引         | 重启 MCP 服务                  |
| 搜到但排名靠后        | 关键词密度不足               | 改写 `##` 标题与正文，补实义词，重建索引    |
| category 过滤查不到 | 分类未同步进工具枚举            | 见 2.3 节，改后 `npm run build` |
| 章节内容被切散        | 主题跨了多个 `##`           | 重排章节结构，让主题收敛在一个 `##` 内     |

## 5. 维护事项清单

- [ ] 新文件遵循命名规范（`NN-topic-name.md`）

- [ ] 每个 `##` 章节自包含、标题含实义词

- [ ] 分类 README.md 总索引已更新（新文件加一行）

- [ ] 新分类已同步 index.ts 的 category 枚举与描述

- [ ] `npm run build-kb` 已执行

- [ ] MCP 服务已重启

- [ ] `get_knowledge_base_stats` 确认统计增长

- [ ] `search_knowledge_base` 用真实 query 实测命中

- [ ] 参数表标注了出处
