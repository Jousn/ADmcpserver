# GJB5000B 与电路设计流程桥接指南

> 本文档将 GJB 5000B-2021 的 21 个实践域映射到 Altium Designer MCP 工具链，
> 说明在原理图/PCB 设计的各个阶段如何落地 GJB5000B 的过程管理要求。
> 版本：v1.0 | 更新日期：2026-09

---

## 1. 桥接总览

GJB 5000B 是**过程管理标准**，不是技术设计规范。它的价值在于：
- 确保设计过程**可追溯、可重复、可量化**
- 将个人经验转化为**组织资产**
- 通过**评审和验证**卡住质量关口

桥接思路：将 GJB5000B 的实践域要求映射到 altium-mcp 工具链的**设计阶段输出物**，让 AI 在绘图过程中自动满足过程管理要求。

## 3. 关键实践域落地指南

### 3.1 配置管理（8.1 CM）— 原理图版本控制

**GJB5000B 要求**：建立配置项、基线、变更控制

**MCP 落地**：
```
1. 配置项识别:
   - 原理图文件 → 配置项（CI）
   - PCB 文件 → 配置项（CI）
   - BOM → 配置项（CI）
   - 网表 → 配置项（CI）

2. 基线建立:
   - 设计基线: 原理图 ERC 通过 + check_connectivity 通过
   - 生产基线: PCB DRC 通过 + BOM 冻结
   - 产品基线: 首件验证通过

3. 变更控制:
   - 每次修改 edit_schematic → 记录变更内容
   - 变更影响分析: 是否影响 PCB 布局/布线
   - 变更审批: 保留审批记录
```

**AI 操作**：每次 `edit_schematic` 后生成变更记录：
```
## 变更记录 CR-XXX
- 日期: 2026-09-15
- 变更内容: U1 从 STM32F103C8T6 更改为 STM32F407VET6
- 影响分析: 引脚不兼容，需重新布局；电源从 3.3V 不变
- 验证: compile_project → 0 errors; check_connectivity → 0 floating
```

### 3.2 验证与确认（7.6 VV）— 编译验证

**GJB5000B 要求**：制定验证计划、执行验证、记录结果

**MCP 落地**：
```
验证计划:
  1. 电气验证: compile_project + check_connectivity
  2. 布局验证: analyze_schematic_quality (交叉/弯曲/绕行)
  3. 规则验证: 对照 design-rules 知识库逐项检查
  4. 选型验证: 对照 component-selection 知识库检查降额

验证执行:
  - compile_project → errors=0, warnings=0
  - check_connectivity → pins_floating=0, short_circuits=0
  - analyze_schematic_quality → score < 阈值
  - pcb_drc → violations=0

验证记录:
  验证报告 VR-XXX
  - 验证项: XXX
  - 验证方法: <MCP工具名>
  - 验证结果: PASS/FAIL
  - 缺陷清单: (如有)
```

### 3.3 同行评审（7.5 PR）— 自动审查

**GJB5000B 要求**：制定评审计划、组织评审、记录问题、跟踪闭环

**MCP 落地**：
```
1. 评审准备:
   - 使用 circuit-review-agent 对原理图进行 8 维度自动审查
   - 生成预审报告，识别高优先级问题

2. 评审执行:
   - 预审报告发给评审人
   - 评审人重点审查 P0/P1 问题
   - 记录评审意见

3. 问题闭环:
   - 每个评审问题有状态: 新建→分析→修复→验证→关闭
   - 修复后重新运行 circuit-review-agent 验证

4. 评审记录:
   评审报告 RR-XXX
   - 评审日期: 2026-09-15
   - 评审人: <姓名>
   - 评审对象: <原理图版本>
   - 问题数: XX (P0: X, P1: X, P2: X)
   - 已关闭: XX
   - 遗留: XX
```

### 3.4 需求开发与管理（7.2 RDM）— 需求追踪

**GJB5000B 要求**：需求识别、分析、追踪、变更管理

**MCP 落地**：
```
需求追踪矩阵（RTM）:
| 需求ID | 需求描述 | 设计实现 | 验证方法 | 状态 |
|--------|----------|----------|----------|------|
| REQ-01 | 5V 输入防反接 | D1 肖特基 D1 | 目视检查 | 已验证 |
| REQ-02 | 过压保护 30V | TVS D2 SMAJ5.0A | check_connectivity | 已验证 |
| REQ-03 | 3.3V 输出 1A | U1 AMS1117-3.3 | compile_project | 已验证 |
| REQ-04 | LED 电源指示 | D3 + R3 1k | 目视检查 | 已验证 |

AI 操作: 绘图完成后自动生成 RTM 草稿，人工补充验证状态。
```

### 3.5 技术解决方案（7.3 TS）— 方案文档

**GJB5000B 要求**：备选方案、选型理由、设计决策记录

**MCP 落地**：
```
方案文档 TD-XXX:
  1. 需求摘要: <从 RDM 追踪>
  2. 备选方案:
     方案A: Buck 降压 (MP1584) — 效率 90%, 成本低
     方案B: LDO (AMS1117) — 效率 60%, 低噪声
     方案C: Buck + LDO — 折中
  3. 选型理由: 方案C, 兼顾效率和噪声
  4. 设计参数:
     - 频率: 500kHz
     - 输出纹波: <10mV
     - 热功耗: 0.5W
  5. 知识库依据: classic-circuits/02-buck-circuits + component-selection/01-opamp
```

### 3.6 产品集成与交付（7.4 PID）— BOM 与网表

**GJB5000B 要求**：集成策略、接口定义、交付验证

**MCP 落地**：
```
交付物清单:
  1. 原理图 PDF (已通过 ERC + check_connectivity)
  2. PCB Gerber (已通过 DRC)
  3. BOM (generate_report 导出)
  4. 网表 (编译分区导出)
  5. 变更记录 (CM 变更日志)
  6. 验证报告 (VV 验证记录)
  7. 评审报告 (PR 评审记录)

BOM 验证:
  - 每个元件有 MPN
  - 供应链状态: Active/NRND/EOL
  - 封装与 PCB 匹配
  - 归一化检查
```

### 3.7 风险与机遇管理（6.3 ROM）— 设计风险

**GJB5000B 要求**：识别风险、分析影响、制定应对

**MCP 落地**：
```
设计风险登记册:
| 风险ID | 描述 | 概率 | 影响 | 应对措施 | 状态 |
|--------|------|------|------|----------|------|
| RSK-01 | 电源 EMI 超标 | 中 | 高 | 加 π 滤波 + 磁珠 | 已采取措施 |
| RSK-02 | 元件 NRND | 低 | 中 | 选型时查供应链状态 | 已规避 |
| RSK-03 | 引脚分配冲突 | 低 | 高 | 原理图编译验证 | 已验证 |
```

### 3.8 测量与绩效管理（8.5 MPM）— 质量度量

**GJB5000B 要求**：定义度量项、采集数据、分析绩效

**MCP 落地**：
```
度量项:
  - 原理图错误密度: errors / 元件数 (目标 <0.1)
  - DRC 违规密度: violations / 元件数 (目标 <0.05)
  - 评审缺陷密度: 问题数 / 百行 (目标 <5)
  - 需求覆盖率: 已实现需求 / 总需求 (目标 100%)
  - 变更返工率: 变更导致返工数 / 变更数 (目标 <20%)

AI 自动采集:
  - compile_project → 错误数
  - check_connectivity → 悬空/短路数
  - analyze_schematic_quality → 质量评分
  - pcb_drc → 违规数
  - get_all_designators → 元件数
```

## 5. 实施建议

### 5.1 对 AI 绘图助手的要求

1. **每次 edit_schematic 后**：自动生成变更记录（CM 变更控制）
2. **每次 compile_project 后**：自动记录验证结果（VV 验证记录）
3. **每次 check_connectivity 后**：自动更新需求追踪矩阵状态（RDM 追踪）
4. **绘图完成时**：自动调用 circuit-review-agent 生成预审报告（PR 评审准备）
5. **交付前**：自动生成交付物清单和度量数据（PID + MPM）

### 5.2 对项目团队的要求

1. 建立 GJB5000B 文件模板（需求矩阵/验证报告/评审记录等）
2. 将 altium-mcp 输出的结构化数据填入模板
3. 定期审查度量数据，识别改进机会（OPI 组织过程改进）
4. 将验证过的设计模式纳入组织资产库（OAD 组织资产开发）
